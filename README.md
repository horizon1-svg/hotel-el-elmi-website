# فندق العلمي — Hotel El Elmi | موقع عرض تمهيدي (Preview)

موقع عرض احترافي لفندق العلمي في الوادي، الجزائر، مُعد كأداة عرض على صاحب الفندق قبل إتمام الاتفاق. لا يعتمد على أي إطار عمل (framework) — HTML و
CSS و JavaScript فقط، بنفس أسلوب مشروعي Sweet King 2 وMazaj.

## ما هو حقيقي وما هو Placeholder

**معلومات حقيقية ومؤكدة** (مُدرجة في `js/data.js`):
- الاسم، الهاتفان، العنوان (حي سيدي عبدالله، الوادي)، الرمز المرجعي للموقع
  (Plus Code)، التقييم الإجمالي على خرائط جوجل (٣.٨ من ٥ بناءً على ٢١٨
  تقييم)، والخدمات الأربع المؤكدة (واي فاي، موقف سيارات، مطعم، استقبال
  ٢٤ ساعة).

**Placeholder صريح — لا تنشروه على أنه حقيقي:**
- كل الصور (البطل، الغرف، المطعم، المعرض) عبارة عن لوحات نمط بديلة، وليست
  صور فعلية للفندق.
- بطاقات الغرف الثلاث في قسم "الغرف والإقامة" متطابقة عمدًا (لا تحمل أسماء
  أو فئات) لأن أنواع الغرف والأسعار غير مؤكدة بعد — لا تُضيفوا أسماء فئات
  (مثل "غرفة مزدوجة" أو "جناح") قبل تأكيدها فعليًا من الفندق.
- قائمة المطعم وساعات العمل: "قيد الإعداد".
- رابط صفحة الفيسبوك: لم يُزوّد رابط رسمي، فقط اسم الصفحة — الحقل
  `facebookUrl` في `data.js` يبقى `null` حتى تأكيد الرابط.
- زر واتساب: لم يُدرج لأن تفعيل واتساب على الرقم غير مؤكد. إذا تأكد أن
  الرقم يعمل على واتساب، غيّروا `whatsappConfirmed` إلى `true` في
  `data.js` ثم أضيفوا زر واتساب في `index.html` (المكان الأنسب: بجانب
  زر الاتصال في القسم اللاصق للجوال `#stickyActionBar`).

## هيكل الملفات

```
hotel-el-elmi/
├── index.html          الموقع العام
├── admin.html          مفهوم لوحة تحكم مستقبلية (بدون تسجيل دخول أو قاعدة بيانات)
├── css/styles.css      كل التنسيقات (الموقع العام + لوحة التحكم)
├── js/data.js          كل المحتوى القابل للتعديل — عدّلوا هنا فقط
├── js/main.js          منطق عرض الموقع العام والتفاعلات
├── js/admin.js         تبديل أقسام لوحة التحكم فقط
└── README.md
```

عند توفر معلومات حقيقية جديدة (أسعار، صور، قائمة مطعم)، التعديل يكون في
`js/data.js` فقط — لا حاجة لتعديل HTML أو CSS.

## استبدال الصور

كل مكان صورة في الموقع معرّف بالكلاس `placeholder-media`. لاستبداله بصورة
حقيقية:
1. ضعوا الصورة في مجلد `assets/` (مثال: `assets/hero.jpg`).
2. في `index.html`، استبدلوا محتوى العنصر (اللوحة النقطية + الأيقونة)
   بوسم `<img src="assets/hero.jpg" alt="وصف الصورة">`.
3. كرروا نفس الخطوة لصور الغرف والمطعم والمعرض عند توفرها — بيانات
   المعرض والغرف تُدار من `js/data.js` (مصفوفات `galleryItems` و`rooms`)
   بحيث يمكن لاحقًا ربطها بمسارات صور حقيقية بدل اللوحات البديلة.

## التشغيل محليًا

لا حاجة لأي أدوات بناء (build tools). افتحوا `index.html` مباشرة في
المتصفح، أو شغّلوا خادمًا محليًا بسيطًا:

```bash
npx serve .
# أو
python3 -m http.server 8080
```

## النشر على GitHub Pages

بنفس أسلوب مشاريع Sweet King 2 وMazaj في هذا الحساب (`horizon1-svg`):
1. أنشئوا مستودعًا جديدًا (يُفضّل اسم غير لافت طالما الاتفاق مع الفندق لم
   يُنجز).
2. ارفعوا كل الملفات كما هي (لا حاجة لخطوة بناء).
3. من إعدادات المستودع، فعّلوا GitHub Pages على الفرع الرئيسي.
4. **قبل النشر العلني الفعلي بعد إتمام الاتفاق**: احذفوا شريط المعاينة
   العلوي (`#previewBanner` في `index.html`) وحذفوا وسم
   `<meta name="robots" content="noindex, nofollow">` من كل من
   `index.html` و`admin.html`.

## المرحلة القادمة: Supabase

مخطط البيانات في `js/data.js` مُصمّم عمدًا ليطابق جداول مستقبلية:

| مصفوفة/كائن في data.js | الجدول المقترح في Supabase |
|---|---|
| `hotelInfo` | `hotel_info` (صف واحد) |
| `amenities` | `amenities` |
| `rooms` | `rooms` |
| `galleryItems` | `gallery_items` |
| `restaurantInfo` | `restaurant_info` (صف واحد) |
| طلبات نموذج الحجز | `booking_requests` |

عند الربط، تُستبدل كل `const` بنداء `fetch`/`supabase.from(...).select()`
بنفس الشكل (shape)، ودوال العرض في `main.js` لا تحتاج تعديلًا. **تنبيه
أمني:** لا يوضع أي مفتاح Supabase من نوع service-role في كود الواجهة
الأمامية — يُستخدم فقط المفتاح العام (anon key) مع صلاحيات (RLS) مضبوطة
بعناية.

## لوحة التحكم (admin.html)

واجهة مفاهيمية فقط توضح شكل الإدارة المستقبلية (نظرة عامة، الغرف، طلبات
الحجز، قائمة المطعم، معرض الصور، معلومات الفندق، رسائل التواصل،
الإعدادات). **لا تحتوي على تسجيل دخول ولا قاعدة بيانات فعلية** — لا
تُنشر رابطها للعامة قبل إضافة نظام مصادقة حقيقي (Supabase Auth مثلًا).

## نموذج الحجز

النموذج في قسم "تواصل معنا" يجمع الطلب محليًا في المتصفح فقط (انظر
`wireBookingForm()` في `js/main.js`) ويعرض رسالة شكر — **لا يُرسل الطلب
إلى أي جهة بعد**، ولا يؤكد الحجز تلقائيًا. الكود يحتوي تعليقًا يوضح مكان
إضافة الاتصال الحقيقي (Supabase insert أو خدمة بريد/إشعارات) لاحقًا.
